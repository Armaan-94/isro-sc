# 5.2 Process Management: PCB, States and Schedulers

> 24 questions.

---

**Q1.** A program becomes a process when:
(a) written (b) compiled (c) loaded into memory with a PCB (d) saved
**Answer: (c).**

**Q2.** NOT in a PCB:
(a) program counter (b) registers (c) the compiler's source code (d) I/O status
**Answer: (c).**

**Q3.** Single CPU, n processes. Maximum in Running?
(a) n (b) n − 1 (c) 1 (d) 0
**Answer: (c).**

**Q4.** Controls the degree of multiprogramming:
(a) short-term (b) long-term (c) medium-term (d) dispatcher
**Answer: (b).**

**Q5.** The short-term scheduler must be fast because:
(a) fewer processes (b) it runs very often (c) once per session (d) speed doesn't matter
**Answer: (b).**

**Q6.** The long-term scheduler should admit:
(a) CPU-bound only (b) I/O-bound only (c) a balanced mix (d) anything
**Answer: (c).**

**Q7.** Context-switch time is:
(a) useful work (b) pure overhead (c) I/O time (d) compile time
**Answer: (b).**

**Q8.** Performs the context switch:
(a) long-term scheduler (b) medium-term scheduler (c) dispatcher (d) job pool
**Answer: (c).** Its delay is dispatch latency.

**Q9.** Single CPU, n processes. Minimum in the Ready state?
(a) 0 (b) 1 (c) n − 1 (d) n
**Answer: (a).** All could be waiting.

**Q10.** Single CPU, n processes. Maximum in the Waiting state?
(a) n − 1 (b) n (c) 1 (d) 0
**Answer: (b).** All could be blocked (CPU idle).

**Q11.** Which transition is impossible?
(a) Ready → Running (b) Running → Waiting (c) Waiting → Running (d) Waiting → Ready
**Answer: (c).** A woken process goes to Ready first.

**Q12.** Running → Ready happens on:
(a) I/O request (b) timer interrupt / preemption (c) exit (d) I/O completion
**Answer: (b).**

**Q13.** Running → Waiting happens on:
(a) time slice expiry (b) an I/O request or event wait (c) dispatch (d) exit
**Answer: (b).**

**Q14.** A zombie process:
(a) has terminated but its parent hasn't collected its status (wait) (b) whose parent died (c) running forever (d) swapped out
**Answer: (a).**

**Q15.** An orphan process:
(a) terminated, not reaped (b) whose parent terminated first; it is adopted by init/systemd (c) a daemon by definition (d) deadlocked
**Answer: (b).**

**Q16.** Medium-term scheduler:
(a) admits jobs (b) swaps processes out and in to adjust multiprogramming (c) dispatches (d) handles interrupts
**Answer: (b).**

**Q17.** Process memory sections:
(a) text, data, heap, stack (b) only stack (c) code and registers (d) cache and RAM
**Answer: (a).**

**Q18.** Local variables live in the:
(a) text (b) data (c) heap (d) stack
**Answer: (d).** Globals in data; malloc'd memory in the heap.

**Q19.** Two processes running the same program share:
(a) nothing by default except possibly the read-only code (b) the stack (c) the heap (d) the PCB
**Answer: (a).**

**Q20.** An I/O-bound process:
(a) spends most time computing (b) spends most time waiting for I/O, with short CPU bursts (c) never uses the CPU (d) is always high priority
**Answer: (b).**

**Q21.** The ready queue is usually implemented as:
(a) a linked list of PCBs (b) an array of programs (c) a stack (d) a hash of files
**Answer: (a).**

**Q22.** During a context switch the most essential items saved are:
(a) the program counter and CPU registers (b) the disk contents (c) the cache (d) the source code
**Answer: (a).**

**Q23.** With 4 CPUs and 10 processes, the maximum number in Running?
(a) 1 (b) 4 (c) 10 (d) 6
**Answer: (b).**

**Q24.** The state a newly created process enters after being admitted:
(a) running (b) ready (c) waiting (d) terminated
**Answer: (b).**
