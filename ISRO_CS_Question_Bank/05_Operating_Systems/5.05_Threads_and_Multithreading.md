# 5.5 Threads and Multithreading Models

> 20 questions.

---

**Q1.** fork() returns in the child:
(a) child's PID (b) 0 (c) parent's PID (d) −1
**Answer: (b).**

**Q2.** Three sequential fork() calls. Total processes?
(a) 3 (b) 6 (c) 7 (d) 8
**Answer: (d).**

**Q3.** One blocking system call blocks all threads in the process under:
(a) one-to-one (b) many-to-many (c) many-to-one (d) none
**Answer: (c).**

**Q4.** Modern Linux and Windows use:
(a) many-to-one (b) one-to-one (c) many-to-many (d) two-to-one
**Answer: (b).**

**Q5.** Shared among threads of one process but not between processes:
(a) program counter (b) stack (c) code and data segments (d) registers
**Answer: (c).** Also heap and open files.

**Q6.** Thread creation is cheaper than process creation because:
(a) no PC (b) it reuses the process's address space and resources (c) not schedulable (d) separate CPU always
**Answer: (b).**

**Q7.** Each thread has its own:
(a) code section (b) global variables (c) stack, registers and program counter (d) open file table
**Answer: (c).**

**Q8.** Threads of one process need synchronisation because:
(a) they share data (heap, globals) (b) they never share anything (c) the OS forbids sharing (d) they run on different machines
**Answer: (a).**

**Q9.** User-level threads are managed by:
(a) the kernel (b) a thread library in user space; the kernel sees one process (c) hardware (d) the compiler only
**Answer: (b).**

**Q10.** Advantage of user-level threads:
(a) fast switching without kernel calls (b) true parallelism (c) blocking doesn't affect others (d) kernel awareness
**Answer: (a).**

**Q11.** Advantage of kernel-level threads:
(a) cheapest creation (b) the kernel can schedule them on multiple CPUs and block them individually (c) no system calls (d) portable libraries
**Answer: (b).**

**Q12.** Many-to-many model:
(a) maps many user threads onto an equal or smaller number of kernel threads (b) one kernel thread only (c) one per user thread (d) no kernel threads
**Answer: (a).**

**Q13.** A thread pool helps by:
(a) reusing pre-created threads, avoiding creation cost per request (b) increasing memory (c) removing synchronisation (d) eliminating context switches
**Answer: (a).**

**Q14.** Context switch between threads of the same process is cheaper because:
(a) the address space (page tables) need not change (b) no registers are saved (c) no scheduler runs (d) threads don't have PCs
**Answer: (a).**

**Q15.** Benefits of multithreading include:
(a) responsiveness, resource sharing, economy, scalability (b) isolation of memory (c) fewer CPUs needed (d) no synchronisation
**Answer: (a).**

**Q16.** The POSIX thread creation call:
(a) fork() (b) pthread_create() (c) exec() (d) clone_thread()
**Answer: (b).**

**Q17.** A program is 80% parallelisable. Maximum speedup on 4 cores (Amdahl)?
(a) 4 (b) 2.5 (c) 3.2 (d) 2
**Answer: (b).** 1/(0.2 + 0.8/4) = 1/0.4.

**Q18.** If one thread of a process calls exit(), typically:
(a) only that thread ends (b) the whole process ends (c) nothing (d) other processes end
**Answer: (b).** pthread_exit() ends just the thread.

**Q19.** A thread is often called a:
(a) heavyweight process (b) lightweight process (c) daemon (d) zombie
**Answer: (b).**

**Q20.** Global variables in a multithreaded program are stored:
(a) once, shared by all threads (b) per thread (c) on each stack (d) in registers
**Answer: (a).** Thread-local storage is the exception.
