# 5.6 Deadlock: Prevention, Avoidance, Detection

> 26 questions. Banker set B (resources A, B, C): Available (3, 3, 2).
> Allocation: P0 (0, 1, 0), P1 (2, 0, 0), P2 (3, 0, 2), P3 (2, 1, 1), P4 (0, 0, 2).
> Max: P0 (7, 5, 3), P1 (3, 2, 2), P2 (9, 0, 2), P3 (2, 2, 2), P4 (4, 3, 3).

---

**Q1.** NOT a necessary condition for deadlock:
(a) mutual exclusion (b) hold and wait (c) starvation (d) circular wait
**Answer: (c).** The fourth is no preemption.

**Q2.** Prevention usually can't deny:
(a) hold and wait (b) mutual exclusion (c) circular wait (d) no preemption
**Answer: (b).** Printers can't be shared.

**Q3.** Available (3, 3, 0); Need P0 (3, 3, 0), P1 (1, 0, 2), P2 (0, 3, 0), P3 (3, 4, 1). Which can't be satisfied immediately?
(a) only P3 (b) P1 and P3 (c) only P1 (d) none
**Answer: (b).** P1 needs 2 of C; P3 needs 4 of B.

**Q4.** RAG cycle, all single-instance resources:
(a) no deadlock (b) deadlock (c) can't say (d) need priority
**Answer: (b).**

**Q5.** RAG cycle with multi-instance resources:
(a) deadlock (b) safe (c) deadlock possible, not certain (d) can't draw
**Answer: (c).**

**Q6.** Approach used by Linux/Windows:
(a) prevention (b) avoidance (c) detection (d) ignore (ostrich)
**Answer: (d).**

**Q7.** Tracking rollbacks per victim prevents:
(a) burst errors (b) starvation of the same victim (c) priority loss (d) nothing
**Answer: (b).**

**Q8.** Set B: Need of P0?
(a) (7, 5, 3) (b) (7, 4, 3) (c) (6, 0, 0) (d) (1, 2, 2)
**Answer: (b).** Max − Allocation.

**Q9.** Set B: total instances of each resource?
(a) (10, 5, 7) (b) (7, 2, 5) (c) (3, 3, 2) (d) (9, 5, 7)
**Answer: (a).** Available + sum of allocations (7, 2, 5).

**Q10.** Set B: which process can be satisfied first?
(a) P0 (b) P1 or P3 (c) P2 (d) P4 only
**Answer: (b).** Needs: P1 (1, 2, 2), P3 (0, 1, 1) fit within (3, 3, 2).

**Q11.** Set B: a safe sequence?
(a) P1, P3, P4, P0, P2 (b) P0, P1, P2, P3, P4 (c) P2, P0, P1, P3, P4 (d) none (unsafe)
**Answer: (a).** Work: (5, 3, 2) → (7, 4, 3) → (7, 4, 5) → (7, 5, 5) → (10, 5, 7).

**Q12.** Set B: P1 requests (1, 0, 2). Grant it?
(a) yes, the resulting state is safe (b) no, exceeds need (c) no, exceeds available (d) no, unsafe
**Answer: (a).** New Available (2, 3, 0); P1 can still finish, then P3, P4, P0, P2.

**Q13.** Set B (original state): P0 requests (0, 2, 0). Result?
(a) granted, the new state is safe (b) must wait, unsafe (c) error, exceeds need (d) deadlock immediately
**Answer: (a).** New Available (3, 1, 2), P0's Need (7, 2, 3). Sequence P3 → (5, 2, 3), P1 → (7, 2, 3), P0 → (7, 5, 3), P2 → (10, 5, 5), P4 → (10, 5, 7). (In the textbook version, where P1's request from Q12 was granted first, this same request leaves the system unsafe.)

**Q14.** n processes each need at most k instances of a resource. Minimum instances that guarantee no deadlock?
(a) nk (b) n(k − 1) + 1 (c) n + k (d) k
**Answer: (b).**

**Q15.** 3 processes each need 2 printers. Minimum printers for deadlock freedom?
(a) 3 (b) 4 (c) 5 (d) 6
**Answer: (b).** 3(2 − 1) + 1.

**Q16.** 6 tape drives; each process needs at most 3. Maximum processes guaranteed deadlock-free?
(a) 2 (b) 3 (c) 4 (d) 6
**Answer: (a).** n(3 − 1) + 1 ≤ 6 → n ≤ 2.

**Q17.** Banker's safety algorithm complexity (m resource types, n processes):
(a) O(m n²) (b) O(n) (c) O(m + n) (d) O(2ⁿ)
**Answer: (a).**

**Q18.** Numbering resources and requesting only in increasing order prevents:
(a) mutual exclusion (b) hold and wait (c) circular wait (d) no preemption
**Answer: (c).**

**Q19.** Requesting all resources at the start prevents:
(a) circular wait (b) hold and wait (c) mutual exclusion (d) preemption
**Answer: (b).** Low utilisation is the price.

**Q20.** A safe state:
(a) guarantees no deadlock (b) means deadlock now (c) is the same as unsafe (d) requires preemption
**Answer: (a).** An unsafe state may (not must) lead to deadlock.

**Q21.** Banker's algorithm needs to know in advance:
(a) each process's maximum demand (b) burst time (c) priority (d) arrival time
**Answer: (a).**

**Q22.** Deadlock detection for single-instance resources uses:
(a) a wait-for graph cycle check (b) the Banker's algorithm only (c) FCFS (d) a TLB
**Answer: (a).** O(n²).

**Q23.** Deadlock vs starvation:
(a) same (b) deadlock = processes wait forever in a cycle; starvation = indefinite postponement while others progress (c) starvation implies deadlock (d) neither exists in real OSes
**Answer: (b).**

**Q24.** Recovering by aborting all deadlocked processes:
(a) is guaranteed but wastes their work (b) is impossible (c) is the cheapest always (d) causes more deadlocks
**Answer: (a).**

**Q25.** Two processes, each holding one resource and requesting the other's. Conditions present?
(a) all four (b) only circular wait (c) only mutual exclusion (d) none
**Answer: (a).**

**Q26.** Allowing the OS to take a resource from a waiting process attacks:
(a) mutual exclusion (b) no preemption (c) circular wait (d) hold and wait
**Answer: (b).**
