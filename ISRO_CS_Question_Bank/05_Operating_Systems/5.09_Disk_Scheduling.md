# 5.9 Disk Scheduling Algorithms

> 24 questions. Cylinders 0–199. SCAN/C-SCAN go to the physical end; LOOK/C-LOOK turn at the last request. The C-SCAN/C-LOOK return jump is counted as head movement.
> Set A: head 53, moving up; requests 98, 183, 37, 122, 14, 124, 65, 67.
> Set B: head 50, moving up; requests 82, 170, 43, 140, 24, 16, 190.

---

**Q1.** Head 50; FCFS requests 20, 90, 60, 150. Total movement?
(a) 180 (b) 220 (c) 260 (d) 300
**Answer: (b).** 30 + 70 + 30 + 90.

**Q2.** "SJF of disk scheduling":
(a) FCFS (b) SSTF (c) SCAN (d) C-LOOK
**Answer: (b).** Can starve far requests.

**Q3.** Travel to the physical disk ends even with no request there:
(a) LOOK, C-LOOK (b) SCAN, C-SCAN (c) FCFS (d) SSTF
**Answer: (b).**

**Q4.** C-SCAN gives more uniform waiting than SCAN because:
(a) fewer requests (b) it always sweeps one way and jumps back (c) starts at 0 (d) same as FCFS
**Answer: (b).**

**Q5.** Set A: smallest total among FCFS, SSTF, SCAN, LOOK?
(a) FCFS (b) SSTF (c) SCAN (d) LOOK
**Answer: (b).** 236 vs 640, 331, 299.

**Q6.** All algorithms behave identically when:
(a) defragmented (b) only one request is pending (c) head at 0 (d) never
**Answer: (b).**

**Q7.** Set A, FCFS total?
(a) 640 (b) 620 (c) 600 (d) 236
**Answer: (a).**

**Q8.** Set A, SSTF total?
(a) 208 (b) 236 (c) 299 (d) 331
**Answer: (b).** 53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183.

**Q9.** Set A, SCAN total?
(a) 299 (b) 331 (c) 382 (d) 236
**Answer: (b).** (199 − 53) + (199 − 14).

**Q10.** Set A, C-SCAN total?
(a) 331 (b) 382 (c) 322 (d) 183
**Answer: (b).** 146 + 199 + 37.

**Q11.** Set A, LOOK total?
(a) 299 (b) 331 (c) 322 (d) 260
**Answer: (a).** (183 − 53) + (183 − 14).

**Q12.** Set A, C-LOOK total?
(a) 299 (b) 322 (c) 382 (d) 236
**Answer: (b).** 130 + 169 + 23.

**Q13.** Is SSTF always optimal?
(a) yes (b) no (Set A optimum is 208: go down to 14 first, then up to 183) (c) only for SCAN (d) only with one request
**Answer: (b).**

**Q14.** Set B, FCFS total?
(a) 642 (b) 600 (c) 208 (d) 332
**Answer: (a).** 32 + 88 + 127 + 97 + 116 + 8 + 174.

**Q15.** Set B, SSTF total?
(a) 208 (b) 242 (c) 314 (d) 332
**Answer: (a).** 50 → 43 → 24 → 16 → 82 → 140 → 170 → 190: 7 + 19 + 8 + 66 + 58 + 30 + 20.

**Q16.** Set B, SCAN total?
(a) 314 (b) 332 (c) 391 (d) 341
**Answer: (b).** (199 − 50) + (199 − 16).

**Q17.** Set B, LOOK total?
(a) 314 (b) 332 (c) 341 (d) 208
**Answer: (a).** (190 − 50) + (190 − 16).

**Q18.** Set B, C-LOOK total?
(a) 314 (b) 341 (c) 391 (d) 332
**Answer: (b).** 140 + 174 + (43 − 16).

**Q19.** Set B, C-SCAN total?
(a) 341 (b) 391 (c) 332 (d) 382
**Answer: (b).** 149 + 199 + 43.

**Q20.** Disk access time =
(a) seek + rotational latency + transfer time (b) seek only (c) rotation only (d) transfer only
**Answer: (a).** Seek usually dominates.

**Q21.** 7200 rpm disk. Average rotational latency?
(a) 8.33 ms (b) 4.17 ms (c) 7.2 ms (d) 1 ms
**Answer: (b).** Half of 60/7200 s.

**Q22.** 16 surfaces, 128 tracks per surface, 256 sectors per track, 512 bytes per sector. Capacity?
(a) 128 MB (b) 256 MB (c) 512 MB (d) 1 GB
**Answer: (b).** 2⁴ · 2⁷ · 2⁸ · 2⁹ = 2²⁸ bytes.

**Q23.** 6000 rpm, 512 KB per track. Data transfer rate?
(a) 25 MB/s (b) 50 MB/s (c) 100 MB/s (d) 5 MB/s
**Answer: (b).** 100 rotations/s × 512 KB.

**Q24.** Best for heavily loaded systems (fair, no starvation):
(a) SSTF (b) SCAN/C-SCAN (c) FCFS (d) random
**Answer: (b).**
