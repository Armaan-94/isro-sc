# 5.10 File Management: Allocation, Free Space, Directories and RAID

> 24 questions.

---

**Q1.** Direct access with no external fragmentation:
(a) contiguous (b) linked (c) indexed (d) none
**Answer: (c).**

**Q2.** Linked allocation's direct access is slow because:
(a) no syntax (b) you must follow pointers block by block (c) i undefined (d) it's fast
**Answer: (b).**

**Q3.** 800,000 blocks. Bit-vector size?
(a) 8,000 B (b) 80,000 B (c) 100,000 B (d) 800,000 B
**Answer: (c).**

**Q4.** Solves name collisions but no user sub-directories:
(a) single-level (b) two-level (c) tree (d) acyclic graph
**Answer: (b).**

**Q5.** General-graph directories must handle:
(a) no links (b) cycles (detection or garbage collection) (c) always faster (d) nothing
**Answer: (b).**

**Q6.** Faster directory lookup:
(a) linked list (b) hash table (c) equal (d) neither
**Answer: (b).**

**Q7.** RAID level with no fault tolerance:
(a) 1 (b) 0 (c) 5 (d) 6
**Answer: (b).**

**Q8.** Distributed parity, survives one disk failure:
(a) RAID 2 (b) RAID 4 (c) RAID 5 (d) RAID 1
**Answer: (c).**

**Q9.** RAID 6 tolerates:
(a) 0 (b) 1 (c) 2 failures (d) unlimited
**Answer: (c).**

**Q10.** Indexed allocation's drawback:
(a) no direct access (b) external fragmentation (c) index-block overhead for small files (d) no large files
**Answer: (c).**

**Q11.** RAID alone doesn't catch silent corruption; fix:
(a) RAID 0 (b) end-to-end checksums (e.g., ZFS) (c) none (d) bigger disks
**Answer: (b).**

**Q12.** Inode with 10 direct pointers and 1 single-indirect pointer; block 1 KB; pointer 4 bytes. Maximum file size?
(a) 10 KB (b) 256 KB (c) 266 KB (d) 1 MB
**Answer: (c).** The indirect block holds 256 pointers: (10 + 256) × 1 KB.

**Q13.** Block 4 KB, pointer 4 bytes. Data reachable through one double-indirect pointer?
(a) 4 MB (b) 4 GB (c) 16 MB (d) 1 GB
**Answer: (b).** 1024 × 1024 blocks × 4 KB.

**Q14.** Five 1 TB disks in RAID 5. Usable capacity?
(a) 5 TB (b) 4 TB (c) 2.5 TB (d) 3 TB
**Answer: (b).** One disk's worth goes to parity.

**Q15.** Six 2 TB disks in RAID 6. Usable capacity?
(a) 12 TB (b) 10 TB (c) 8 TB (d) 6 TB
**Answer: (c).** Two disks' worth of parity.

**Q16.** RAID 1 storage efficiency:
(a) 100% (b) 50% (c) 75% (d) 33%
**Answer: (b).** Mirroring.

**Q17.** Contiguous allocation suffers from:
(a) external fragmentation and difficulty growing files (b) slow sequential access (c) no direct access (d) pointer overhead
**Answer: (a).**

**Q18.** FAT (File Allocation Table) is a variant of:
(a) linked allocation with pointers kept in a table (b) contiguous (c) indexed with inodes (d) RAID
**Answer: (a).** Random access improves because the table can be cached.

**Q19.** A hard link:
(a) points to the same inode; the file survives until the link count is 0 (b) stores a path (c) breaks when the target is renamed (d) can cross file systems freely
**Answer: (a).** A symbolic link stores a path and can dangle.

**Q20.** In acyclic-graph directories, files are deleted when:
(a) any link is removed (b) the reference count reaches 0 (c) never (d) the owner logs out
**Answer: (b).**

**Q21.** Bitmap size for a 1 TB disk with 4 KB blocks?
(a) 32 MB (b) 256 MB (c) 1 GB (d) 4 MB
**Answer: (a).** 2⁴⁰/2¹² = 2²⁸ blocks → 2²⁸ bits = 2²⁵ bytes = 32 MB.

**Q22.** Mounting a file system:
(a) attaches it to the directory tree at a mount point (b) formats it (c) deletes it (d) defragments it
**Answer: (a).**

**Q23.** Which structure holds per-file metadata in Unix?
(a) superblock (b) inode (c) boot block (d) directory only
**Answer: (b).** The filename is stored in the directory entry, not the inode.

**Q24.** Best allocation for a file that is only read sequentially and grows often:
(a) contiguous (b) linked (c) none (d) RAID 0
**Answer: (b).**
