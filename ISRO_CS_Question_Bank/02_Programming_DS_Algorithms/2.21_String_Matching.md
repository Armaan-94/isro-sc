# 2.21 String Matching Algorithms

**Notes:** [21 String Matching Algorithms](../../PDSA_ISRO_Notes/21_String_Matching_Algorithms.md)

> 20 questions. Text length n, pattern length m.

---

**Q1.** T = "AABAACAADAABAABA", P = "AABA". Match positions (1-indexed)?
(a) 1, 5, 9 (b) 1, 10, 13 (c) 1, 4, 10 (d) 10, 13, 16
**Answer: (b).**

**Q2.** Worst case of naive matching:
(a) O(n + m) (b) O(n log m) (c) O(nm) (d) O(log n)
**Answer: (c).**

**Q3.** Rabin-Karp verifies characters after a hash match because:
(a) it doesn't need to (b) different strings can share a hash (spurious hit) (c) to recompute the hash (d) only for long patterns
**Answer: (b).**

**Q4.** "31415" in "2359023141526739921" occurs at position:
(a) 3 (b) 5 (c) 7 (d) none
**Answer: (c).**

**Q5.** Guaranteed O(n + m) worst case:
(a) naive (b) Rabin-Karp (c) KMP (d) none
**Answer: (c).**

**Q6.** Rabin-Karp updates the window hash in O(1) using:
(a) recomputation (b) a rolling hash (c) sorting (d) threads
**Answer: (b).**

**Q7.** Naive matching tries how many alignments?
(a) n (b) n − m + 1 (c) m (d) nm
**Answer: (b).**

**Q8.** Naive worst-case character comparisons for n = 10, m = 3?
(a) 24 (b) 30 (c) 8 (d) 13
**Answer: (a).** (n − m + 1) × m = 8 × 3.

**Q9.** KMP prefix (failure) function of "ABABAC"?
(a) 0 0 1 2 3 0 (b) 0 1 2 3 4 0 (c) 0 0 1 2 0 0 (d) 0 0 0 1 2 0
**Answer: (a).** π[i] = length of the longest proper prefix that is also a suffix of P[1..i].

**Q10.** Prefix function of "AAAA"?
(a) 0 0 0 0 (b) 0 1 2 3 (c) 1 2 3 4 (d) 0 1 1 1
**Answer: (b).**

**Q11.** Prefix function of "ABCDABD"?
(a) 0 0 0 0 1 2 0 (b) 0 0 0 0 1 2 3 (c) 0 0 0 1 2 3 0 (d) 0 0 0 0 0 0 0
**Answer: (a).**

**Q12.** KMP preprocessing time and space:
(a) O(m), O(m) (b) O(n), O(1) (c) O(nm) (d) O(m²)
**Answer: (a).**

**Q13.** In KMP, the text pointer:
(a) moves backwards on a mismatch (b) never moves backwards (c) restarts at 0 (d) moves randomly
**Answer: (b).** That's why it's linear.

**Q14.** Rabin-Karp best/average case:
(a) O(nm) (b) O(n + m) (c) O(n log n) (d) O(m²)
**Answer: (b).** Worst case O(nm) with many collisions.

**Q15.** Rabin-Karp is especially handy for:
(a) searching many patterns at once (b) sorting (c) compression only (d) graphs
**Answer: (a).** Compare each window hash against a set of pattern hashes.

**Q16.** Non-empty substrings (by position) of a string of length 5?
(a) 10 (b) 15 (c) 25 (d) 31
**Answer: (b).** n(n + 1)/2. (31 = 2⁵ − 1 is the number of non-empty subsequences.)

**Q17.** Boyer-Moore compares the pattern:
(a) left to right (b) right to left, skipping using bad-character/good-suffix rules (c) by hashing (d) randomly
**Answer: (b).** Often sublinear in practice.

**Q18.** The finite-automaton matcher, after preprocessing, scans the text in:
(a) O(n) (b) O(nm) (c) O(n log n) (d) O(m)
**Answer: (a).** Preprocessing is O(m |Σ|).

**Q19.** Naive matching best case (first character mismatches at most shifts):
(a) O(1) (b) O(n) (c) O(nm) (d) O(m)
**Answer: (b).**

**Q20.** A spurious hit in Rabin-Karp is:
(a) a hash match that isn't a real match (b) a real match missed (c) a pattern of length 1 (d) a collision in the text only
**Answer: (a).**
