# 2.17 Searching Algorithms and Min-Max

**Notes:** [17 Searching and MinMax](../../PDSA_ISRO_Notes/17_Searching_and_MinMax.md)

> 22 questions.

---

**Q1.** Binary search on 1024 sorted elements: maximum comparisons?
(a) 1024 (b) 512 (c) 10 or 11 (d) 100
**Answer: (c).** About log₂ 1024 = 10 halvings; counting the final probe gives ⌊log₂ n⌋ + 1 = 11. Options typically list 10 as "log₂ n".

**Q2.** FALSE about binary search:
(a) needs sorted data (b) worst case O(log n) (c) efficient on singly linked lists (d) recursive version uses O(log n) stack
**Answer: (c).**

**Q3.** Straight min-max on a strictly decreasing array of 20 elements. Comparisons?
(a) 19 (b) 20 (c) 38 (d) 40
**Answer: (c).** 2(n − 1).

**Q4.** Divide-and-conquer min-max for n = 64?
(a) 63 (b) 94 (c) 126 (d) 96
**Answer: (b).** ⌈3n/2⌉ − 2.

**Q5.** Divide-and-conquer min-max for n = 250?
(a) 373 (b) 375 (c) 498 (d) 249
**Answer: (a).**

**Q6.** Why not sort, then binary search, for a single query?
(a) impossible (b) sorting costs O(n log n), more than one O(n) linear scan (c) uses more memory (d) no reason
**Answer: (b).** Sorting pays off over many queries.

**Q7.** Recursive binary search reports "not found" when:
(a) mid equals key (b) low > high (c) the array is empty at the start only (d) stack overflow
**Answer: (b).**

**Q8.** Search 47 in [3, 9, 15, 22, 31, 40, 47, 58, 66, 72] with mid = ⌊(low + high)/2⌋. Elements probed?
(a) 31, 58, 40, 47 (b) 31, 47 (c) 40, 58, 47 (d) 22, 47
**Answer: (a).** Indices 4, 7, 5, 6.

**Q9.** Average comparisons for a successful linear search (each position equally likely)?
(a) n (b) n/2 (c) (n + 1)/2 (d) log n
**Answer: (c).**

**Q10.** Straight min-max on an increasing array of n elements (checking max first)?
(a) n − 1 (b) 2(n − 1) (c) 3n/2 (d) n
**Answer: (a).** Each element beats max, so the min check is skipped.

**Q11.** Interpolation search on uniformly distributed keys: average case?
(a) O(log n) (b) O(log log n) (c) O(n) (d) O(1)
**Answer: (b).** Worst case O(n).

**Q12.** Jump search with block size √n:
(a) O(log n) (b) O(√n) (c) O(n) (d) O(n log n)
**Answer: (b).**

**Q13.** Comparisons to find the second largest of n elements (tournament method)?
(a) 2n − 3 (b) n + ⌈log₂ n⌉ − 2 (c) n − 1 (d) n log n
**Answer: (b).** For n = 8: 9.

**Q14.** Searching in a sorted array that has been rotated:
(a) O(n) only (b) O(log n) with modified binary search (c) O(1) (d) impossible
**Answer: (b).**

**Q15.** Binary search recurrence:
(a) T(n) = 2T(n/2) + 1 (b) T(n) = T(n/2) + 1 (c) T(n) = T(n − 1) + 1 (d) T(n) = T(n/2) + n
**Answer: (b).**

**Q16.** Space of iterative binary search:
(a) O(1) (b) O(log n) (c) O(n) (d) O(n log n)
**Answer: (a).**

**Q17.** Min-max D&C recurrence:
(a) T(n) = 2T(n/2) + 2 (b) T(n) = T(n/2) + 1 (c) T(n) = 2T(n/2) + n (d) T(n) = T(n − 1) + 2
**Answer: (a).** Base T(2) = 1.

**Q18.** Linear search best case:
(a) O(1) (b) O(log n) (c) O(n) (d) O(n²)
**Answer: (a).**

**Q19.** Exponential search finds a range by:
(a) doubling the index until it passes the key, then binary searching (b) halving (c) hashing (d) jumping √n
**Answer: (a).** Useful for unbounded lists.

**Q20.** Maximum comparisons for binary search on 1000 elements?
(a) 9 (b) 10 (c) 11 (d) 500
**Answer: (b).** ⌊log₂ 1000⌋ + 1 = 9 + 1.

**Q21.** Both min-max methods have complexity:
(a) Θ(log n) (b) Θ(n) (c) Θ(n log n) (d) Θ(n²)
**Answer: (b).** D&C only improves the constant (1.5n vs 2n).

**Q22.** Binary search requires:
(a) a linked list (b) sorted data with random access (c) a hash table (d) unique keys only
**Answer: (b).**
