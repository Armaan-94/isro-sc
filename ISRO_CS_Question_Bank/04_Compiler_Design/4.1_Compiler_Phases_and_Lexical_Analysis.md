# 4.1 Phases of a Compiler and Lexical Analysis

> 26 questions. Token counting: whitespace and comments are not tokens; a string literal is one token; the lexer always takes the longest match.

---

**Q1.** Order of the first three phases:
(a) syntax, lexical, semantic (b) lexical, syntax, semantic (c) semantic, lexical, syntax (d) lexical, semantic, syntax
**Answer: (b).**

**Q2.** "Undeclared variable" is detected in:
(a) lexical (b) syntax (c) semantic analysis (d) code generation
**Answer: (c).**

**Q3.** Front-end (analysis) phases are:
(a) machine-dependent (b) machine-independent (c) only for interpreters (d) skipped
**Answer: (b).**

**Q4.** The matched text "total" is the:
(a) token (b) lexeme (c) pattern (d) attribute
**Answer: (b).** IDENTIFIER is the token; the regular expression is the pattern.

**Q5.** Lexical analysers are built from:
(a) PDAs (b) TMs (c) finite automata from regular expressions (d) CSGs
**Answer: (c).**

**Q6.** Maximal munch means:
(a) shortest match (b) longest match (c) single characters (d) ignore whitespace
**Answer: (b).** ">=" is one token.

**Q7.** The lexer alone can NOT detect:
(a) an illegal character (b) a malformed number (c) unbalanced parentheses (d) an unterminated string
**Answer: (c).** That needs the parser.

**Q8.** The symbol table is used:
(a) only after code generation (b) throughout all phases (c) only in lexing (d) never
**Answer: (b).**

**Q9.** Back-end (synthesis) phases:
(a) lexical, syntax (b) semantic, IC generation (c) optimisation and code generation (d) code generation only
**Answer: (c).**

**Q10.** Identifiers are described by regular expressions because:
(a) they need nesting (b) their pattern is regular, so a fast DFA suffices (c) regexes are for syntax only (d) can't be tokenised
**Answer: (b).**

**Q11.** Tokens in `printf("i = %d", i);`?
(a) 5 (b) 7 (c) 9 (d) 10
**Answer: (b).** printf ( "i = %d" , i ) ;

**Q12.** Tokens in `int a = b + 10;`?
(a) 6 (b) 7 (c) 8 (d) 5
**Answer: (b).** int a = b + 10 ;

**Q13.** Tokens in `x = y+++z;`?
(a) 6 (b) 7 (c) 8 (d) 5
**Answer: (b).** x = y ++ + z ; (longest match takes ++ first).

**Q14.** A missing semicolon is detected in:
(a) lexical (b) syntax (c) semantic (d) runtime
**Answer: (b).**

**Q15.** Adding an int to a struct (type mismatch) is detected in:
(a) lexical (b) syntax (c) semantic (d) linker
**Answer: (c).**

**Q16.** Division by a variable that happens to be zero is detected at:
(a) lexical (b) syntax (c) semantic (d) runtime
**Answer: (d).**

**Q17.** The lexer also usually:
(a) removes whitespace and comments (b) allocates registers (c) checks types (d) optimises loops
**Answer: (a).**

**Q18.** Tools for generating lexer and parser:
(a) LEX and YACC (b) YACC and LEX respectively (c) GCC and LD (d) Make and Ant
**Answer: (a).** LEX makes lexers; YACC makes LALR(1) parsers.

**Q19.** A cross-compiler:
(a) runs on one machine and produces code for another (b) compiles two languages (c) is an interpreter (d) links objects
**Answer: (a).**

**Q20.** Compiler vs interpreter:
(a) compiler translates the whole program first; interpreter executes statement by statement (b) the reverse (c) identical (d) interpreters produce object files
**Answer: (a).**

**Q21.** The linker:
(a) combines object files and resolves external references (b) loads programs into memory only (c) tokenises (d) optimises
**Answer: (a).** The loader places the program in memory for execution.

**Q22.** The preprocessor runs:
(a) after code generation (b) before the compiler proper (c) at runtime (d) inside the linker
**Answer: (b).**

**Q23.** A two-pass assembler builds the symbol table in:
(a) pass 1 (b) pass 2 (c) both (d) neither
**Answer: (a).** Pass 2 generates code using it.

**Q24.** Intermediate code is useful mainly because:
(a) it is executable (b) it separates front end from back end, allowing reuse and machine-independent optimisation (c) it replaces lexing (d) it is faster than machine code
**Answer: (b).**

**Q25.** Bootstrapping is:
(a) writing a compiler in the language it compiles (b) loading the OS (c) linking (d) lexing
**Answer: (a).**

**Q26.** Lexical analysis corresponds to which Chomsky type?
(a) Type 0 (b) Type 1 (c) Type 2 (d) Type 3
**Answer: (d).** Parsing is Type 2.
