# 4.6 Symbol Tables, Runtime Environment and Code Generation

> 24 questions.

---

**Q1.** A symbol table stores per identifier:
(a) name only (b) name, type, scope, storage location (c) address only (d) the source text
**Answer: (b).**

**Q2.** Handling shadowing in nested scopes needs:
(a) one flat table (b) nested/scoped tables or a scope stack (c) alphabetical table (d) rebuilding per statement
**Answer: (b).**

**Q3.** The control (dynamic) link points to:
(a) the lexically enclosing function's record (b) the caller's activation record (c) the next instruction (d) heap memory
**Answer: (b).**

**Q4.** The access (static) link supports:
(a) dynamic scoping (b) static scoping for nested functions (c) register allocation (d) folding
**Answer: (b).**

**Q5.** Static scoping resolves names by:
(a) the runtime caller (b) where the name is declared in the source (c) a config file (d) global values
**Answer: (b).**

**Q6.** Static allocation can't support recursion because:
(a) too slow (b) every call would share the same fixed locations for locals (c) only globals (d) no locals
**Answer: (b).**

**Q7.** Stack allocation works for recursion because:
(a) fixed addresses (b) each call pushes its own activation record (c) no return address needed (d) GC
**Answer: (b).**

**Q8.** Register allocation by graph colouring:
(a) alphabetical (b) colour the interference graph so simultaneously live variables get different registers (c) one register each (d) globals only
**Answer: (b).** NP-hard in general.

**Q9.** Heap allocation:
(a) lifetime tied to a call (b) lifetime independent of calls; explicit free or garbage collection (c) fixed compile-time address (d) freed on return
**Answer: (b).**

**Q10.** Function f is nested inside g, and f calls itself recursively. In the newest activation record of f:
(a) both links point to the previous f record (b) the control link points to the previous f record; the access link points to g's record (c) both point to g (d) undefined
**Answer: (b).** The caller is the previous f call, but f is lexically nested in g.

**Q11.** Which is NOT usually part of an activation record?
(a) return address (b) local variables (c) the symbol table (d) saved registers
**Answer: (c).** The symbol table is a compile-time structure.

**Q12.** Returning the address of a local variable creates a:
(a) memory leak (b) dangling reference (c) stack overflow (d) compile-time error always
**Answer: (b).** The frame is gone after return.

**Q13.** Reference counting garbage collection fails to reclaim:
(a) any object (b) cyclic structures (c) large objects (d) strings
**Answer: (b).** Mark-and-sweep handles cycles.

**Q14.** `void f(int x, int y) { x = x + 1; y = y + 1; }`, a = 1, call f(a, a). Value of a after the call under call-by-reference?
(a) 1 (b) 2 (c) 3 (d) 4
**Answer: (c).** x and y both alias a.

**Q15.** Same call under call-by-value-result (copy in, copy out)?
(a) 1 (b) 2 (c) 3 (d) 4
**Answer: (b).** x and y each become 2; both copy back 2.

**Q16.** Same call under call-by-value?
(a) 1 (b) 2 (c) 3 (d) 4
**Answer: (a).**

**Q17.** In call-by-name, an argument expression is:
(a) evaluated once before the call (b) re-evaluated every time the parameter is used (c) copied back (d) never evaluated
**Answer: (b).** Jensen's device exploits this.

**Q18.** Three variables are live at the same time at some point, and never more. Minimum registers needed without spilling (assuming the interference graph's chromatic number equals that maximum)?
(a) 1 (b) 2 (c) 3 (d) 4
**Answer: (c).**

**Q19.** A display is:
(a) an array of pointers to the current activation records at each nesting level (b) the output device (c) a symbol table (d) a heap
**Answer: (a).** Faster alternative to following access links.

**Q20.** Symbol tables are usually implemented as:
(a) hash tables (b) linked lists only (c) arrays sorted at runtime (d) stacks only
**Answer: (a).**

**Q21.** Instruction selection is often done by:
(a) tree-pattern matching against instruction templates (b) lexing (c) LL parsing (d) hashing
**Answer: (a).**

**Q22.** Languages that need heap allocation for activation records (not a stack):
(a) those with closures that outlive their creating call (b) C (c) FORTRAN 77 (d) assembly
**Answer: (a).**

**Q23.** Dynamic scoping would be implemented by following:
(a) access links (b) control links (c) the heap (d) the symbol table at compile time
**Answer: (b).**

**Q24.** The return address in an activation record tells:
(a) where the caller resumes after the call (b) where locals are (c) the heap top (d) the program start
**Answer: (a).**
