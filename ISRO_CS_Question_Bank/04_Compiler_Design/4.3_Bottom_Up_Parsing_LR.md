# 4.3 Bottom-Up Parsing: LR(0), SLR, LALR, CLR

> 24 questions. Power: LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ CLR(1). States: LR(0) = SLR = LALR ≤ CLR.

---

**Q1.** Bottom-up parsing corresponds to:
(a) leftmost derivation forward (b) rightmost derivation in reverse (c) neither (d) leftmost in reverse
**Answer: (b).**

**Q2.** A reduce action:
(a) pushes input (b) replaces a handle on the stack top with the production's left side (c) clears the stack (d) backtracks
**Answer: (b).**

**Q3.** Correct power ordering:
(a) LR(0) ⊂ SLR ⊂ LALR ⊂ CLR (b) the reverse (c) equal (d) SLR ⊂ LR(0)
**Answer: (a).**

**Q4.** LALR(1) vs SLR(1):
(a) more states, less power (b) same states, more power (c) fewer states, less power (d) identical
**Answer: (b).**

**Q5.** Dangling else causes a:
(a) reduce-reduce conflict (b) shift-reduce conflict (c) lexical error (d) left recursion
**Answer: (b).**

**Q6.** Reduce-reduce conflict:
(a) shift vs reduce (b) two productions could be reduced at the same state (c) lexical (d) no non-terminals
**Answer: (b).**

**Q7.** Default resolution of dangling else:
(a) reduce (b) shift: else binds to the nearest if (c) reject (d) random
**Answer: (b).**

**Q8.** Uses no lookahead for reduce decisions:
(a) CLR (b) LALR (c) SLR (d) LR(0)
**Answer: (d).**

**Q9.** SLR(1) reduces by A → α when the lookahead is in:
(a) FIRST(α) (b) FOLLOW(A) (c) all terminals (d) nothing
**Answer: (b).**

**Q10.** YACC uses LALR(1) because:
(a) it beats CLR (b) near-CLR power with SLR-sized tables (c) CLR can't handle languages (d) no lookahead
**Answer: (b).**

**Q11.** Number of LR(0) items from A → abc?
(a) 3 (b) 4 (c) 1 (d) 6
**Answer: (b).** Dot in each of 4 positions.

**Q12.** LR(0) items from A → ε?
(a) 0 (b) 1 (A → •) (c) 2 (d) undefined
**Answer: (b).**

**Q13.** The augmented grammar adds:
(a) S' → S (b) S → ε (c) $ → S (d) S → S'
**Answer: (a).** Acceptance happens on reducing S' → S.

**Q14.** Merging CLR(1) states into LALR(1) can introduce:
(a) new shift-reduce conflicts (b) new reduce-reduce conflicts only (c) no conflicts ever (d) lexical errors
**Answer: (b).** Shift actions depend only on the core, which is identical, so no new shift-reduce conflicts.

**Q15.** An ambiguous grammar is:
(a) LR(1) (b) not LR(k) for any k (c) LALR only (d) SLR only
**Answer: (b).**

**Q16.** Every LL(1) grammar is:
(a) LR(1) (b) LR(0) (c) SLR(1) (d) not LR
**Answer: (a).** Not necessarily LALR or SLR.

**Q17.** A handle is:
(a) any substring (b) a right-hand side whose reduction is a step of the reverse rightmost derivation (c) the start symbol (d) a terminal
**Answer: (b).**

**Q18.** An operator grammar has:
(a) no ε-productions and no two adjacent non-terminals on any right side (b) only terminals (c) left recursion (d) CNF
**Answer: (a).** Used by operator-precedence parsers.

**Q19.** A viable prefix is:
(a) a prefix of a right-sentential form that can appear on the parser stack (b) any input prefix (c) the FIRST set (d) a token
**Answer: (a).**

**Q20.** LR parsers are preferred over LL because:
(a) they handle a larger class of grammars, including left recursion (b) easier by hand (c) smaller tables always (d) no stack
**Answer: (a).**

**Q21.** Number of states: CLR(1) compared to LALR(1):
(a) fewer or equal (b) greater or equal (c) always equal (d) unrelated
**Answer: (b).**

**Q22.** In a shift-reduce parser, the actions are:
(a) shift, reduce, accept, error (b) push, pop only (c) scan, match (d) predict, match
**Answer: (a).**

**Q23.** S → AA, A → aA | b. Is it LR(0)?
(a) yes (b) no, shift-reduce conflict (c) no, reduce-reduce (d) ambiguous
**Answer: (a).** Each completed item sits alone in its state. This is the standard textbook LR(0)/SLR example.

**Q24.** A grammar with a shift-reduce conflict in SLR but not in CLR:
(a) is not SLR(1), but may be LR(1) (b) is ambiguous (c) is not context-free (d) is LL(1)
**Answer: (a).**
