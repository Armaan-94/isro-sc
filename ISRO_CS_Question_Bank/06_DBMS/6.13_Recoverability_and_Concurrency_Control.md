# 6.13 Recoverability and Concurrency Control Protocols

> 26 questions. Hierarchy: Strict ⊂ Cascadeless ⊂ Recoverable ⊂ all schedules. "Dirty read" = reading an uncommitted write.

---

**Q1.** W1(X); R2(X); C1; C2:
(a) not recoverable (b) recoverable, not cascadeless (c) cascadeless, not recoverable (d) strict
**Answer: (b).**

**Q2.** Containment:
(a) Recoverable ⊂ Cascadeless ⊂ Strict (b) Strict ⊂ Cascadeless ⊂ Recoverable (c) all equal (d) Cascadeless ⊂ Strict ⊂ Recoverable
**Answer: (b).**

**Q3.** Timestamp ordering rejects Read(Q) by Ti when:
(a) TS(Ti) < R-TS(Q) (b) TS(Ti) < W-TS(Q) (c) TS(Ti) > W-TS(Q) (d) equal
**Answer: (b).**

**Q4.** Thomas's write rule relaxes:
(a) both rules (b) only the write rule: obsolete writes are ignored (c) all rollbacks (d) makes deadlock possible
**Answer: (b).**

**Q5.** Deadlock-free 2PL variant:
(a) basic (b) strict (c) conservative (d) rigorous
**Answer: (c).**

**Q6.** Does basic 2PL guarantee recoverability?
(a) yes (b) no (c) only with X locks (d) only for reads
**Answer: (b).**

**Q7.** Strict vs rigorous 2PL:
(a) strict holds X locks till commit; rigorous holds all locks till commit (b) rigorous has no growing phase (c) strict isn't two-phase (d) same
**Answer: (a).**

**Q8.** View serializable but not conflict serializable schedules can be produced by:
(a) strict 2PL (b) conservative 2PL (c) Thomas's write rule (d) basic TO
**Answer: (c).**

**Q9.** No dirty reads at all means the schedule is:
(a) only recoverable (b) recoverable and cascadeless (c) neither (d) strict
**Answer: (b).**

**Q10.** W1(X); R2(X); C2; C1:
(a) recoverable (b) not recoverable (c) strict (d) cascadeless
**Answer: (b).** The reader commits before the writer.

**Q11.** W1(X); C1; R2(X); C2:
(a) not recoverable (b) recoverable only (c) strict (d) cascadeless only
**Answer: (c).**

**Q12.** W1(X); W2(X); C1; C2 (no reads):
(a) strict (b) cascadeless but not strict (c) not recoverable (d) not cascadeless
**Answer: (b).** T2 writes X before T1 commits.

**Q13.** Lock compatibility:
(a) S-S compatible; S-X and X-X incompatible (b) all compatible (c) X-X compatible (d) S-X compatible
**Answer: (a).**

**Q14.** 2PL guarantees:
(a) conflict serializability (b) deadlock freedom (c) cascadelessness (d) all of these
**Answer: (a).**

**Q15.** The equivalent serial order under 2PL follows:
(a) the order of lock points (b) arrival order (c) commit order always (d) random
**Answer: (a).** Lock point = when a transaction acquires its last lock.

**Q16.** Is every conflict serializable schedule producible under 2PL?
(a) yes (b) no (c) only strict (d) only conservative
**Answer: (b).** 2PL ⇒ conflict serializable, not the reverse.

**Q17.** Timestamp ordering is:
(a) deadlock-free (b) deadlock-prone (c) not serializable (d) strict
**Answer: (a).** Transactions are rolled back instead of waiting.

**Q18.** TS(T1) = 5. Item Q has W-TS = 10. T1 issues Read(Q). Result?
(a) allowed (b) T1 rolled back (c) ignored (d) waits
**Answer: (b).**

**Q19.** TS(T1) = 5, Q has R-TS = 10, W-TS = 0. T1 issues Write(Q). Result?
(a) allowed (b) rolled back (c) ignored (Thomas) (d) waits
**Answer: (b).** A younger transaction has already read Q.

**Q20.** TS(T1) = 5, Q has R-TS = 0, W-TS = 10. T1 writes Q. Basic TO vs Thomas's rule?
(a) both roll back (b) basic rolls back; Thomas ignores the write (c) both allow (d) both ignore
**Answer: (b).**

**Q21.** Wait-die scheme: an older transaction requests a lock held by a younger one. It:
(a) waits (b) dies (c) wounds the younger (d) restarts the younger
**Answer: (a).** A younger requester held up by an older one dies (restarts with the same timestamp).

**Q22.** Wound-wait scheme: an older transaction requests a lock held by a younger one. It:
(a) waits (b) dies (c) wounds (preempts) the younger (d) does nothing
**Answer: (c).** A younger requester waits for an older holder.

**Q23.** Cascading rollback is prevented by:
(a) cascadeless schedules (no dirty reads) (b) recoverability alone (c) TO (d) basic 2PL
**Answer: (a).**

**Q24.** In 2PL, the growing phase:
(a) only acquires locks (b) only releases (c) does both freely (d) is optional
**Answer: (a).**

**Q25.** Multiple-granularity locking uses intention locks such as:
(a) IS, IX, SIX (b) R, W (c) TS, WTS (d) LSN
**Answer: (a).**

**Q26.** Optimistic (validation-based) concurrency control suits:
(a) workloads with mostly reads and few conflicts (b) heavy write conflicts (c) single-user systems only (d) none
**Answer: (a).**
