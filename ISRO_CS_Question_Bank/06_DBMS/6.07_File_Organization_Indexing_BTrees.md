# 6.7 File Organization, Indexing and B/B+ Trees

**Notes:** [07 File Organization Indexing BTrees](../../DBMS_ISRO_Notes/07_File_Organization_Indexing_BTrees.md)

> 24 questions. bfr = ⌊block size / record size⌋; blocks = ⌈records / bfr⌉. Single-level index with binary search: ⌈log₂(index blocks)⌉ + 1. Multilevel index: levels + 1.

---

**Q1.** Always dense:
(a) primary index (b) clustering index (c) secondary index (d) multilevel index
**Answer: (c).**

**Q2.** A single-level index occupies 2000 blocks. Worst-case block accesses for binary search on the index plus one data-block access?
(a) 10 (b) 11 (c) 12 (d) 2000
**Answer: (c).** ⌈log₂ 2000⌉ + 1 = 11 + 1.

**Q3.** B+ trees are preferred because:
(a) less memory (b) unbalanced (c) linked leaves for range queries and higher fan-out (d) B-trees limited to 3 levels
**Answer: (c).**

**Q4.** B-tree of order 5: minimum keys in a non-root internal node?
(a) 1 (b) 2 (c) 3 (d) 4
**Answer: (b).** ⌈5/2⌉ − 1.

**Q5.** B-tree of order 5: maximum keys per node?
(a) 3 (b) 4 (c) 5 (d) 6
**Answer: (b).**

**Q6.** B+ tree leaf split: the median key is:
(a) deleted (b) moved up and removed from the leaf (c) copied up and kept in the leaf (d) ignored
**Answer: (c).** In a B-tree it moves up.

**Q7.** "B-trees beat B+ trees because data can be found at internal nodes." Flaw?
(a) correct (b) no internal nodes (c) poor range-query support outweighs this (d) only B-trees balanced
**Answer: (c).**

**Q8.** B+ tree underflow with no sibling to borrow from:
(a) ignored (b) merge with a sibling, possibly cascading and lowering height (c) permanent imbalance (d) new root always
**Answer: (b).**

**Q9.** 30,000 records of 100 B, blocks of 1024 B. Blocks in the main file?
(a) 2930 (b) 3000 (c) 300 (d) 30,000
**Answer: (b).** bfr 10.

**Q10.** Same file; index entries of 15 B (9 B key + 6 B pointer). Primary (sparse) index blocks?
(a) 44 (b) 45 (c) 442 (d) 68
**Answer: (b).** 68 entries per block; 3000/68 → 45.

**Q11.** Block accesses using that primary index with binary search (single level)?
(a) 6 (b) 7 (c) 3 (d) 10
**Answer: (b).** ⌈log₂ 45⌉ + 1.

**Q12.** Same, but as a two-level index?
(a) 2 (b) 3 (c) 4 (d) 7
**Answer: (b).**

**Q13.** A secondary (dense) index on the same file needs how many first-level blocks?
(a) 45 (b) 442 (c) 3000 (d) 68
**Answer: (b).** 30,000/68 → 442.

**Q14.** Block size 512 B, record 100 B. Blocking factor?
(a) 4 (b) 5 (c) 6 (d) 5.12
**Answer: (b).**

**Q15.** 1000 records with bfr 5 in an unordered file. Worst-case block accesses for linear search?
(a) 100 (b) 200 (c) 1000 (d) 8
**Answer: (b).** Average 100.

**Q16.** Same 200 blocks but ordered on the search key. Binary search accesses?
(a) 7 (b) 8 (c) 9 (d) 200
**Answer: (b).** ⌈log₂ 200⌉.

**Q17.** B+ tree internal node: block 512 B, key 10 B, child pointer 6 B. Maximum children (order)?
(a) 31 (b) 32 (c) 33 (d) 51
**Answer: (b).** 6p + 10(p − 1) ≤ 512 → p ≤ 32.6.

**Q18.** B+ tree leaf: entries of (key 10 B + record pointer 6 B) plus one 6 B next-leaf pointer, block 512 B. Maximum keys per leaf?
(a) 30 (b) 31 (c) 32 (d) 51
**Answer: (b).** 16k + 6 ≤ 512 → k ≤ 31.6.

**Q19.** Fan-out 100, 1,000,000 records. Minimum B+ tree levels?
(a) 2 (b) 3 (c) 4 (d) 6
**Answer: (b).** 100³ = 10⁶.

**Q20.** Clustering index entries =
(a) number of records (b) number of distinct values of the clustering field (c) number of blocks (d) 1
**Answer: (b).**

**Q21.** In a B-tree, all leaves are:
(a) at the same level (b) at random levels (c) at most two levels apart (d) linked
**Answer: (a).** B+ tree leaves are also linked.

**Q22.** Binary search on an ordered file works only when searching on:
(a) any field (b) the ordering field (c) the primary key only, even if unsorted (d) indexed fields only
**Answer: (b).**

**Q23.** Heap (unordered) file: cheap and expensive operations are:
(a) cheap insertion, expensive search (b) cheap search (c) cheap deletion and search (d) both expensive
**Answer: (a).**

**Q24.** Which is stored only at the leaves of a B+ tree?
(a) routing keys (b) data/record pointers (c) child pointers (d) nothing
**Answer: (b).**
