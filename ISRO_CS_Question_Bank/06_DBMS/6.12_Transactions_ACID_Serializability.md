# 6.12 Transactions, ACID Properties and Serializability

**Notes:** [12 Transactions ACID Serializability](../../DBMS_ISRO_Notes/12_Transactions_ACID_Serializability.md)

> 26 questions. Precedence graph: edge Ti → Tj for each conflicting pair (same item, different transactions, at least one write) where Ti's operation comes first. Acyclic ⇔ conflict serializable.

---

**Q1.** T1 has 3 operations, T2 has 2. Non-serial schedules?
(a) 10 (b) 8 (c) 120 (d) 6
**Answer: (b).** 5!/(3! 2!) − 2!.

**Q2.** Two reads of the same item by different transactions:
(a) always conflict (b) never conflict (c) depends on isolation (d) only in strict schedules
**Answer: (b).**

**Q3.** S: R1(x) R1(y) R2(x) R2(y) W2(y) W1(x). Conflict serializable?
(a) yes, as T1, T2 (b) yes, as T2, T1 (c) no, cycle (d) can't say
**Answer: (c).** R2(x) before W1(x) gives T2 → T1; R1(y) before W2(y) gives T1 → T2.

**Q4.** True:
(a) view serializable ⇒ conflict serializable (b) conflict serializable ⇒ view serializable (c) always identical (d) neither implies the other
**Answer: (b).**

**Q5.** A cyclic precedence graph with blind writes. The schedule is:
(a) not view serializable (b) possibly view serializable; check directly (c) always view serializable (d) strict
**Answer: (b).**

**Q6.** Serial schedules of n transactions:
(a) n (b) n! (c) 2ⁿ (d) n²
**Answer: (b).**

**Q7.** T2 reads T1's write; T1 later aborts. This is a:
(a) lost update (b) dirty read (c) unrepeatable read (d) phantom
**Answer: (b).**

**Q8.** S: R2(x) W2(x) R2(y) W2(y) R1(y) W1(x). Edges?
(a) T1 → T2 (b) T2 → T1 only (c) cycle (d) none
**Answer: (b).** Equivalent to serial T2, T1.

**Q9.** True:
(a) all view serializable are conflict serializable (b) conflict ⇒ view, and not view ⇒ not conflict (c) unrelated (d) view easier to test
**Answer: (b).** Testing view serializability is NP-complete.

**Q10.** Isolation is ensured by the:
(a) recovery manager (b) concurrency control manager (c) programmer (d) OS
**Answer: (b).** Atomicity and durability: recovery manager; consistency: programmer/constraints.

**Q11.** Durability means:
(a) committed changes survive failures (b) all or nothing (c) no interference (d) constraints hold
**Answer: (a).**

**Q12.** Transaction states after executing the last statement but before being safely on disk:
(a) active (b) partially committed (c) committed (d) failed
**Answer: (b).**

**Q13.** T1 and T2 with 2 operations each. Total schedules?
(a) 4 (b) 6 (c) 24 (d) 2
**Answer: (b).** 4!/(2! 2!).

**Q14.** T1 (2 ops), T2 (2 ops), T3 (1 op). Non-serial schedules?
(a) 24 (b) 30 (c) 6 (d) 120
**Answer: (a).** 5!/(2! 2! 1!) = 30, minus 3! = 6 serial.

**Q15.** Reading the same item twice in a transaction gives different values because another transaction committed an update in between. This is:
(a) dirty read (b) unrepeatable read (c) phantom read (d) lost update
**Answer: (b).**

**Q16.** Re-running a range query shows new rows inserted by another transaction. This is:
(a) phantom read (b) dirty read (c) lost update (d) deadlock
**Answer: (a).**

**Q17.** Two transactions write the same item; one write is overwritten without being seen. This is:
(a) lost update (b) phantom (c) dirty read (d) cascading abort
**Answer: (a).**

**Q18.** S: R1(A) R2(B) W1(A) R3(A) W2(B) W3(A). Conflict serializable?
(a) no (b) yes; T1 must precede T3, T2 unconstrained (c) yes; only T1, T2, T3 (d) can't say
**Answer: (b).**

**Q19.** Operations conflict when:
(a) different transactions, same item, at least one write (b) same transaction (c) different items (d) both reads
**Answer: (a).**

**Q20.** A blind write is:
(a) a write without a prior read of that item by the same transaction (b) a write by an aborted transaction (c) a read without a write (d) a write of NULL
**Answer: (a).**

**Q21.** S: W1(A) W2(A) W1(A). Precedence edges?
(a) T1 → T2 and T2 → T1 (cycle) (b) T1 → T2 only (c) none (d) T2 → T1 only
**Answer: (a).** Not conflict serializable.

**Q22.** S: R1(A) W2(A) W1(A) W3(A) (no other operations). Conflict serializable?
(a) yes (b) no (c) can't say (d) only view
**Answer: (b).** R1(A) before W2(A): T1 → T2; W2(A) before W1(A): T2 → T1. (It is view serializable as T1, T2, T3: T1 reads the initial A and T3 writes last.)

**Q23.** A valid equivalent serial order from an acyclic precedence graph is any:
(a) topological order (b) reverse order (c) random order (d) BFS order only
**Answer: (a).**

**Q24.** Consistency in ACID is mainly the responsibility of:
(a) the programmer/integrity constraints (b) the recovery manager (c) the OS (d) the hardware
**Answer: (a).**

**Q25.** Why allow concurrent execution at all?
(a) better throughput and resource utilisation, lower waiting time (b) simpler code (c) stronger consistency (d) fewer locks
**Answer: (a).**

**Q26.** Every serial schedule is:
(a) consistent (assuming each transaction is correct) (b) non-recoverable (c) deadlocked (d) not serializable
**Answer: (a).**
