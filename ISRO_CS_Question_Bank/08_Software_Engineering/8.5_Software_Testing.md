# 8.5 Software Testing: Levels, Techniques and Coverage

> 26 questions. Boundary value analysis for n independent inputs: normal BVA 4n + 1 cases; robust BVA 6n + 1; worst-case 5ⁿ.

---

**Q1.** Top-down integration uses dummy lower modules called:
(a) drivers (b) stubs (c) mocks (d) harnesses
**Answer: (b).**

**Q2.** Drivers in bottom-up integration simulate:
(a) called modules (b) calling (higher-level) modules (c) test data (d) compilers
**Answer: (b).**

**Q3.** Acceptance testing by real users at their site:
(a) alpha (b) beta (c) unit (d) regression
**Answer: (b).**

**Q4.** Black-box testing is based on:
(a) code structure (b) the specification only (c) cyclomatic complexity (d) coverage
**Answer: (b).**

**Q5.** Valid range 1–100. BVA values:
(a) 1, 100 (b) 50 (c) 0, 1, 2, 99, 100, 101 (d) 1 to 100
**Answer: (c).** (Robust form, including invalid neighbours.)

**Q6.** Equivalence partitioning:
(a) test every value (b) one representative per partition (c) boundaries only (d) skip testing
**Answer: (b).**

**Q7.** 100% statement coverage guarantees:
(a) 100% branch coverage (b) every statement ran, not every branch (c) no defects (d) path coverage
**Answer: (b).**

**Q8.** Coverage strength, weakest to strongest:
(a) path, condition, branch, statement (b) statement, branch, condition, path (c) equal (d) condition, statement, path, branch
**Answer: (b).** (Pure condition coverage doesn't strictly imply branch coverage; condition/decision coverage does.)

**Q9.** Integration testing verifies:
(a) one function alone (b) interfaces between unit-tested modules (c) legal compliance (d) UI looks
**Answer: (b).**

**Q10.** Big-bang integration:
(a) staged top-down (b) all modules at once; hard to isolate defects (c) load testing (d) acceptance testing
**Answer: (b).**

**Q11.** Valid age range 18–60. Robust BVA values?
(a) 17, 18, 19, 59, 60, 61 (b) 18, 60 (c) 0, 100 (d) 30, 40
**Answer: (a).**

**Q12.** Valid range 1–100. Number of equivalence classes (invalid below, valid, invalid above)?
(a) 1 (b) 2 (c) 3 (d) 100
**Answer: (c).**

**Q13.** Normal BVA test cases for a function of 2 inputs?
(a) 5 (b) 9 (c) 13 (d) 25
**Answer: (b).** 4n + 1.

**Q14.** Robust BVA for 2 inputs?
(a) 9 (b) 13 (c) 25 (d) 49
**Answer: (b).** 6n + 1.

**Q15.** Worst-case BVA for 2 inputs?
(a) 9 (b) 13 (c) 25 (d) 36
**Answer: (c).** 5².

**Q16.** Re-running tests after a change to ensure nothing broke:
(a) regression testing (b) smoke testing (c) alpha testing (d) unit testing
**Answer: (a).**

**Q17.** A quick check that the build's basic functions work before deeper testing:
(a) smoke testing (b) mutation testing (c) stress testing (d) beta testing
**Answer: (a).**

**Q18.** Mutation testing evaluates:
(a) the quality of a test suite by introducing small faults (b) performance (c) usability (d) security
**Answer: (a).**

**Q19.** Error, fault, failure:
(a) a human mistake (error) causes a defect in code (fault), which may cause wrong behaviour at runtime (failure) (b) all the same (c) failure causes error (d) fault is a user action
**Answer: (a).**

**Q20.** "Testing can show the presence of bugs, not their absence" is attributed to:
(a) Dijkstra (b) Brooks (c) Boehm (d) Parnas
**Answer: (a).**

**Q21.** Testing beyond normal load to find the breaking point:
(a) stress testing (b) load testing (c) unit testing (d) regression
**Answer: (a).** Load testing checks behaviour at expected peak load.

**Q22.** White-box testing is usually done by:
(a) developers (b) end users (c) marketing (d) customers only
**Answer: (a).**

**Q23.** Minimum test cases for full branch coverage of code with V(G) = 4 (basis path testing):
(a) 2 (b) 4 (c) 8 (d) 16
**Answer: (b).** One per independent path.

**Q24.** Alpha testing is done:
(a) at the developer's site with selected users (b) at customer sites (c) by automated tools only (d) after release
**Answer: (a).**

**Q25.** Testing order from smallest scope:
(a) unit, integration, system, acceptance (b) system, unit, integration, acceptance (c) acceptance first (d) integration first
**Answer: (a).**

**Q26.** Decision table testing suits:
(a) logic with many combinations of conditions and actions (b) performance (c) GUI layout (d) compilation
**Answer: (a).**
