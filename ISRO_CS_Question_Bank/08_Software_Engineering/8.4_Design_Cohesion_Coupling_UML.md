# 8.4 Software Design: Cohesion, Coupling and UML

> 24 questions. Cohesion (worst → best): coincidental, logical, temporal, procedural, communicational, sequential, functional. Coupling (worst → best): content, common, control, stamp, data.

---

**Q1.** Ideal design:
(a) high coupling, high cohesion (b) low, low (c) low coupling, high cohesion (d) high coupling, low cohesion
**Answer: (c).**

**Q2.** Best cohesion:
(a) coincidental (b) temporal (c) procedural (d) functional
**Answer: (d).**

**Q3.** Worst coupling:
(a) data (b) content (c) stamp (d) control
**Answer: (b).**

**Q4.** Grouped only because they run at the same time (initialisation):
(a) functional (b) sequential (c) temporal (d) data coupling
**Answer: (c).**

**Q5.** Passing a flag that controls the callee's logic:
(a) data coupling (b) control coupling (c) common (d) content
**Answer: (b).**

**Q6.** Aggregation vs composition:
(a) same (b) in composition the part can't exist without the whole; in aggregation it can (c) inheritance only (d) one object only
**Answer: (b).**

**Q7.** Use case diagram:
(a) message order (b) actors and system functions (c) class attributes (d) object states
**Answer: (b).**

**Q8.** Sequence diagram shows:
(a) static classes (b) time-ordered messages between objects (c) all states (d) schedule
**Answer: (b).**

**Q9.** Passing a whole record when only part is needed:
(a) common (b) stamp coupling (c) content (d) none
**Answer: (b).**

**Q10.** State chart diagram models:
(a) attributes (b) an object's states and transitions (c) cost (d) schema
**Answer: (b).**

**Q11.** Modules sharing global variables:
(a) data coupling (b) common coupling (c) stamp (d) control
**Answer: (b).**

**Q12.** One element's output feeds the next element:
(a) sequential cohesion (b) communicational (c) procedural (d) logical
**Answer: (a).**

**Q13.** Elements operating on the same data:
(a) communicational cohesion (b) temporal (c) coincidental (d) functional
**Answer: (a).**

**Q14.** "All input routines" grouped together but doing different things:
(a) logical cohesion (b) functional (c) sequential (d) temporal
**Answer: (a).**

**Q15.** Diagram showing physical hardware nodes and where software runs:
(a) deployment diagram (b) class diagram (c) use case (d) activity
**Answer: (a).**

**Q16.** Diagram resembling a flowchart for workflows:
(a) activity diagram (b) sequence (c) class (d) component
**Answer: (a).**

**Q17.** UML 2 diagram categories:
(a) structural and behavioural (b) logical and physical only (c) static only (d) dynamic only
**Answer: (a).** 14 diagrams: 7 structural, 7 behavioural.

**Q18.** Inheritance in a class diagram is shown by:
(a) a hollow triangle arrowhead pointing to the parent (generalisation) (b) a filled diamond (c) a hollow diamond (d) a dashed line
**Answer: (a).** Filled diamond: composition; hollow diamond: aggregation.

**Q19.** Level 0 DFD is also called the:
(a) context diagram (b) ER diagram (c) class diagram (d) state chart
**Answer: (a).** The whole system as one process.

**Q20.** Information hiding (Parnas) means:
(a) modules hide their internal design decisions behind interfaces (b) encrypting code (c) removing comments (d) global variables
**Answer: (a).**

**Q21.** A good design generally has:
(a) high fan-in, low fan-out (b) low fan-in, high fan-out (c) high both (d) zero fan-in
**Answer: (a).** High fan-in suggests reuse; high fan-out suggests a module doing too much.

**Q22.** Singleton pattern ensures:
(a) one instance of a class with a global access point (b) many instances (c) observers notified (d) adapters
**Answer: (a).**

**Q23.** Observer pattern:
(a) dependents are notified automatically when a subject changes state (b) one instance (c) builds objects step by step (d) adapts interfaces
**Answer: (a).**

**Q24.** Multiplicity "1..*" on an association end means:
(a) one or more (b) exactly one (c) zero or one (d) zero or more
**Answer: (a).**
